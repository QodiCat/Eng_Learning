# 产品任务入口

本目录存放产品事实（PRD、配套文件、阶段划分），与工程事实（AGENTS.md、.agents/）分离。

## 如何执行产品类任务

- 新需求清洗与整理：执行提示词库中的《PRD清洗提示词》。本次按用户 2026-10-02 会话提供的版本执行。
- 功能包开发与迭代：执行提示词库中的《Loop工程提示词》。未提供该提示词时，不臆造其流程。
- PRD 批准：由用户明确确认后，Agent 在对应 delivery-status.md 中写入“PRD 已批准”并附日期与确认人。
- 新需求与新反馈先落盘为本目录下的条目，再进入 Loop；不要在 Loop 会话里口头塞需求。

## 本轮清洗约束

- 原始输入为根目录 README.md；客户后续答复优先于旧表述，冲突及出处记录在澄清记录中。
- 每轮一个功能域、至多五问；建议与选项不是客户决定，未答复不得视为同意。
- 阻断性疑问解决后，询问用户“排雷清单已全部解决，是否进入 PRD 撰写？”；得到确认后才撰写。
- 可后置事项必须标注 TBD、负责人及恢复条件，并明确相关部分不能开发，不视为已解决。
- 配套文件为同前缀的 `prd.md`、`schedule-quote.md`、`delivery-status.md`、`traceability.md`，各头部标注同一功能包名与 PRD 版本。
- PRD 承载使用对象、范围、目标、功能 ID、异常边界、本期不包含、验收标准与待决事项；商务信息单独存放，实现信息由开发阶段回填。
- 商务字段未知留空；研发、测试、部署、客户验收初始为未开始；PRD 初稿记为待批准。批准记录仅在 delivery-status.md 生效。
